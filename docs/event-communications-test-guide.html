Event Communications — How to test

Phase 1 test sheet · 4 October 2026 · Do not send live audience mail until you authorize it.

Tickets, receipts, certificates, and lifecycle reminders stay on cPanel SMTP. Campaigns use Resend. Live audience sends stay blocked until RESEND_LIVE_SENDS=1 is set after the domain is verified.

1. After Coolify pulls this deploy

  1. Confirm the app is on one replica. The campaign outbox worker is in-process and is not safe on two containers yet.
  2. Open Admin → Access control. Super Admin and Content Manager should now show campaigns.view, campaigns.manage, and campaigns.send. Log out and back in if the Campaigns item is missing.
  3. Open /admin/campaigns. You should see an empty list and an amber sandbox notice if live sends are off.
  4. Open any event profile. New tabs: Campaigns and Resources.
Safe default: leave RESEND_API_KEY, RESEND_WEBHOOK_SECRET, and RESEND_LIVE_SENDS empty until you are ready. The UI and drafts work without them. Test sends need an API key. Audience sends also need RESEND_LIVE_SENDS=1.

2. Automated checks (no live people)

On your laptop, from the repo:

npx vitest run shared/emailCampaign.test.js shared/emailDesignCompile.test.js server/__tests__/emailCommunications.test.js src/__tests__/rbacPermissions.test.js server/__tests__/ticketService.test.js

Expect those files to pass. They use a fake Resend client and synthetic recipients. They never mail real registrants.

3. Admin walkthrough (sandbox)

A. Create a draft

  1. Go to an event with a few test registrations, or create a cheap/free test event and register yourself only.
  2. Event profile → Campaigns → New campaign, or /admin/campaigns → New campaign.
  3. Purpose: start with Event service (does not need marketing consent).
  4. Wizard steps: Details → Audience → Design → Review / Test → Send / Schedule → Report.
  5. On Design, try each starter: Event update, Joining instructions, Resources and workbook, Thank you and feedback.
  6. Switch Visual / Blocks / Preview. Desktop and mobile preview should show navy #141D45 and teal #00A79D.
  7. Insert merge tags such as {{first_name}} and {{event_title}}. Save design.

B. Audience preview

  1. On Audience, keep status confirmed or clear filters as needed.
  2. Click Preview audience. Included + excluded counts should match the event, not other events.
  3. Country and tags must not appear. Those fields do not exist.
  4. The notice should say the count can change until send, because the snapshot freezes only at dispatch.

C. Test send (needs Resend API key, not live flag)

  1. In Coolify env (or local .env) set RESEND_API_KEY only. Do not set RESEND_LIVE_SENDS=1 yet.
  2. Redeploy or restart the container.
  3. Review / Test → enter your address → Send test.
  4. Subject should start with [TEST].
  5. Open the message. Check logo, event details, and that links go to the app (preferences / resources), not a raw file URL.
Confirm send to the audience must still fail with “Live campaign sends are disabled…” until RESEND_LIVE_SENDS=1. That is correct.

4. Resources

  1. Event profile → Resources. Create one Public and one Registrant link item.
  2. Upload a small PDF. The note must say files are not malware-scanned and stay unpublished until you publish.
  3. Verified access must be disabled / labeled Phase 2.
  4. Publish the public file. Open /resources/EVENT_ID signed out. You should see the public title and be able to download.
  5. Do not publish the registrant-link file, then try its URL. You should get not found / not published.
  6. Publish it. Without a token the download must fail. A token from a campaign email should work. After Revoke links, that token must fail.
  7. Expired or revoked links should show the branded “Link expired” page, not a stack trace.

5. Consent, unsubscribe, reports

  1. Register for a test event. The marketing checkbox must be unchecked by default. Wording: occasional updates about future Mutale events; optional; not required to attend.
  2. Leave it unchecked. You may still receive event service campaigns for that registration.
  3. A promotional campaign preview should exclude that address with no_marketing_consent.
  4. Check the box on a second registration (or Stay subscribed on the preferences page). Promotional preview should now include that address.
  5. Open /email/preferences?token=… from a test email. Loading the page must not unsubscribe you. Only the button should change state.
  6. Confirm unsubscribe. Later promotional jobs must skip that address.
  7. Report tab: included / delivered / bounced. Opens and clicks are labeled as estimates.

7. When you are ready for a real Resend test (still not production audience)

  1. Create a Resend account. Add API key and webhook secret in Coolify env. Do not commit them.
  2. Webhook URL: https://YOUR_DOMAIN/api/webhooks/resend. Events: sent, delivered, delivery_delayed, bounced, complained, failed, opened, clicked.
  3. Verify mutalemubanga.org in Resend (DKIM CNAMEs). Do not change DNS until you decide to.
  4. Only after you explicitly want live audience sends: set RESEND_LIVE_SENDS=1 and restart.
  5. First live send: one event, event-service purpose, audience = you (or a tiny confirmed list you control). Confirm send.
  6. Watch Coolify logs for outbox ticks, then the campaign Report and the Resend dashboard.
  7. Manual inbox checklist (not automated): Gmail, Outlook, Apple Mail on phone and desktop.
Do not set RESEND_LIVE_SENDS=1 on production until the domain is verified and you have approved a real send. Transactional SMTP must keep working for tickets and receipts the whole time.

8. Regression: SMTP still works

  1. Register for an event (or buy a ticket). You should still get the usual branded confirmation / ticket from grow@mutalemubanga.org via cPanel SMTP, not Resend.
  2. If you have a certificate or receipt job, that mail should also still go out on SMTP.
